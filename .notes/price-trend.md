# Price Trend (% เปลี่ยน 1D / 1W / 1M)

## Purpose
เมลรายวันบอกแค่ P/L จากต้นทุน ซึ่งเป็นตัวเลขสะสมตั้งแต่วันซื้อ มองไม่ออกว่า "ช่วงนี้" ราคาไปทางไหน
เพิ่ม % เปลี่ยนของราคา 3 ช่วง (1 วัน / 1 สัปดาห์ / 1 เดือน) ทั้งรายตัวและระดับพอร์ต

## Scope
- % เปลี่ยนรายตัว 3 ช่วง แสดงเป็นบรรทัดย่อยใต้ราคา — ไม่เพิ่มคอลัมน์ เพราะตาราง 680px เต็มแล้ว
  และคอลัมน์ Stoch/RSI ต้องคงเดิมทุกอย่าง
- % เปลี่ยนระดับพอร์ต 3 ช่วง + จำนวนบาทของ 1D ในกล่องสรุป
- คำนวณจาก `Adj Close` — วันขึ้น XD ราคา Close ดิบจะตกเท่าเงินปันผลทำให้ดูเหมือนหุ้นร่วง
  ทั้งที่ไม่ได้ร่วง; ตรงกับที่ `indicators.compute_signals` ใช้ราคา adjusted อยู่แล้ว
- ไม่มีข้อมูลพอ (หุ้นเข้าใหม่ / df สั้น) → แสดง `-` ไม่ใช่ 0

## Out Of Scope
- YTD และช่วงอื่น
- alert ใน subject เมื่อราคาขยับแรง (subject คงเดิม: Partial / High Vol)
- เก็บ state/history ข้ามวัน — ทุกตัวเลขคำนวณจาก df 1y ที่ดึงมาอยู่แล้ว ไม่มี fetch เพิ่ม
- ปันผล (yield, ปันผลรับ) และ % น้ำหนักพอร์ต — เจ้าของพอร์ตแยกไปทำโปรเจกต์อื่น

## Design
- `indicators.price_changes(df)` → `{"d1","w1","m1"}` เป็น % ปัด 1 ตำแหน่ง หรือ `None`
  - 1D = เทียบแท่งก่อนหน้า
  - 1W / 1M = `Series.asof(anchor - 7 วัน / - 1 เดือน)` — คืนแท่งล่าสุดที่ไม่เกินวันนั้น
    จึงข้ามวันหยุด/วันไม่มีเทรดให้เอง ไม่ต้องนับแท่งแบบ `iloc[-6]` ที่เพี้ยนเวลาตลาดปิดยาว
  - anchor = แท่งล่าสุดใน df ไม่ใช่วันนี้ → ข้อมูลค้างหนึ่งวันก็ยังเทียบถูกช่วง
- `high_volume_alert` เลิกคำนวณ `price_change_pct` เองจาก Close ดิบ → เรียก `price_changes(df)["d1"]`
  เลข 1D สองที่ในเมลเดียวกันจะได้ตรงกัน และลดโค้ดซ้ำ
- `pnl.portfolio_changes(positions, usdthb)` ย้อนมูลค่าฐานจาก % ที่คำนวณแล้ว (`base = value / (1+pct)`)
  ไม่ต้องส่งราคาย้อนหลังเข้ามาอีกชุด
  - ข้ามตัวที่ % เป็น None ทั้งฝั่ง now และ base เพื่อให้เทียบกันบนชุดเดียวกัน
  - `usdthb is None` → หุ้น USD ไม่ถูกนับ ตรงกับพฤติกรรมของ `portfolio_totals` เดิม
  - ใช้เรทวันนี้ทั้งสองฝั่ง = วัดการเคลื่อนไหวของราคาล้วน ไม่ปนผลค่าเงิน

## Decisions
- **ปัดเศษที่ชั้นแสดงผลเท่านั้น** (`report._fmt_pct` / `_pct_color`) `price_changes` คืนค่าเต็มความละเอียด
  รอบแรกปัดใน `price_changes` แล้ว `portfolio_changes` เอา % ที่ปัดแล้วไปย้อนหามูลค่าฐาน ทำให้ยอด
  "วันนี้" คลาด ฿26–45 บนพอร์ต ฿639k (วัดจริง) และ worst case ~฿320 ซึ่งพอพลิกเครื่องหมายได้ในวันที่
  พอร์ตขยับน้อย — ปัดที่จุดแสดงผลจุดเดียวแก้ได้ทั้งเรื่องนี้และ `-0.0%`
- `-0.04%` ปัดแล้วได้ `-0.0` ต้องแสดง `0.0%` สีเทา ไม่ใช่ `-0.0%` สีแดง — คุมที่ `_fmt_pct`/`_pct_color`
  ครอบทั้งบรรทัดรายตัว บรรทัดพอร์ต และคอลัมน์ราคาเปลี่ยนของ High Volume
- **1W ต้องใช้ `DateOffset(days=7)` ไม่ใช่ `Timedelta(days=7)`** — สัปดาห์ที่ตลาดสหรัฐปรับเวลาเข้าฤดูร้อน
  `Timedelta` คือ 168 ชั่วโมงจริง ได้ `03-02 23:00 EST` แล้ว `asof` หลุดไปอีกแท่ง กลายเป็นช่วง 8 วัน
  (`DateOffset` ยึด wall clock จึงได้ `03-03 00:00` ตามต้องการ) — Codex จับได้ตอนรีวิวรอบสอง
- เครื่องหมายและสีของบรรทัด "วันนี้" อิงยอด**บาทที่แสดงจริง** (ปัดแล้ว) ไม่ใช่ค่า raw — วันที่พอร์ตนิ่งสนิท
  จะได้ `฿0 (0.0%)` สีเทา ไม่ใช่ `+฿0` สีเขียว
- ตรวจแล้วว่า `DateOffset(months=1)` บน index tz-aware ข้ามเส้น DST ของตลาดสหรัฐยังได้เวลาเดิมตาม
  wall clock ไม่คลาดไปหนึ่งแท่ง จึงไม่ต้อง normalize เพิ่ม
- `high_volume_alert` เรียก `price_changes` ซ้ำอีกรอบต่อ ticker — ยอมรับได้ (คำนวณบน df 250 แถว)
  แลกกับการไม่ต้องส่ง changes เข้าไปเป็นพารามิเตอร์
